Use attributes to give every product in your marketplace the same typed vocabulary, from sizes and materials to capacities and yes/no flags.

An attribute is a typed field that operators define once and attach to products in the shared master catalog. It describes products the same way across every store, feeds storefront filters, and, when it’s a variant axis, decides which variants a product can have. The Product Attribute module holds the attributes and their values. Links connect them to Medusa’s products, categories, and product options, so a variant axis is a real Medusa `ProductOption` underneath.

<Note>
  The data models are `ProductAttribute` (id prefix `pattr`) and `ProductAttributeValue` (id prefix `pattrval`), resolved with `MercurModules.PRODUCT_ATTRIBUTE` from `@mercurjs/types`. Attributes belong to the catalog, never to a store.
</Note>

## Key features

The Product Attribute module covers the full life of a catalog attribute:

- **Five types**: `single_select`, `multi_select`, `text`, `unit`, and `toggle`, each storing its values differently
- **Variant axes**: a `multi_select` attribute with `is_variant_axis` creates a Medusa `ProductOption` that variants bind to
- **Global or inline**: define an attribute once for the whole catalog, or create a one-off attribute on a single product
- **Category scoping**: link an attribute to product categories so it’s offered only for products in them
- **Storefront filters**: shoppers filter products by axis values, and `is_filterable` tells your storefront which attributes to show as facets
- **One batch workflow**: attach, detach, and update all of a product’s attributes in a single run
- **Hooks and events**: catalog workflows expose hooks and emit `product-attribute.*` and `product-attribute-value.*` events

## How it works

An attribute reaches a product in four steps:

1. An operator runs `createProductAttributesWorkflow`. For a variant axis, it also creates a global `ProductOption` with the same values.
2. A product is created with Mercur’s `createProductsWorkflow`, or edited with `createAndLinkProductAttributesToProductWorkflow`, and picks the attributes and values it uses.
3. Selected values link to the product. For an axis, the product also gets the option with only the selected subset of values.
4. Variants bind to the axis option by its title, for example `{ Size: "M" }`, and the storefront filters products by those option values.
