Create a seller’s payout account from server code, for example in an operator route or a custom signup flow. The Vendor API already does this for sellers at `POST /vendor/payout-accounts`.

## Before you begin

You need:

- A seller id, such as `sel_01JD8Q1234567`
- A payout provider. Without one, the `system` provider creates accounts that are `active` at once
- For Stripe Connect, `@mercurjs/payout-stripe-connect` registered on the payout module, as in the [Stripe Connect integration](/resources/integrations/stripe-connect)

## Create the account

<Steps>
  <Step title="Add a route that runs the workflow">
    Create an admin route that takes the seller id from the path and the provider data from the body:

    ```ts title="src/api/admin/payout-setup/[id]/route.ts"
    import type {
      AuthenticatedMedusaRequest,
      MedusaResponse,
    } from "@medusajs/framework/http"
    import { createPayoutAccountWorkflow } from "@mercurjs/core/workflows"

    type Body = { country: string }

    export async function POST(
      req: AuthenticatedMedusaRequest<Body>,
      res: MedusaResponse
    ) {
      const { result } = await createPayoutAccountWorkflow(req.scope).run({
        input: {
          seller_id: req.params.id,
          data: { country: req.body.country },
        },
      })

      res.status(201).json({ payout_account: { id: result.id } })
    }
    ```

    The workflow validates the seller has no account, creates it through the provider, and links it to the seller. The response returns only the id, because `result.data` holds the full provider object.
  </Step>
  <Step title="Call the route">
    Send the seller’s country. Stripe Connect requires `country` and throws `"country" is required` without it:

    ```bash
    curl -X POST http://localhost:9000/admin/payout-setup/sel_01JD8Q1234567 \
      -H "Authorization: Bearer your_admin_token" \
      -H "Content-Type: application/json" \
      -d '{ "country": "US" }'
    ```

    With Stripe Connect, the new account is `pending` and its `data` holds the Express account Stripe created.
  </Step>
</Steps>

## Handle a seller that already has an account

`validateSellerPayoutAccountStep` runs first and throws a `MedusaError` of type `INVALID_DATA` with the message `Seller already has a payout account`. Medusa returns it as a `400`. To reuse the existing account instead, look it up through the seller link:

```ts
const { data: [seller] } = await query.graph({
  entity: "seller",
  fields: ["id", "payout_account.id", "payout_account.status"],
  filters: { id: "sel_01JD8Q1234567" },
})
```

## What happens when the provider call fails

The module creates the `PayoutAccount` row before it calls the provider. If the provider throws, the module deletes that row and rethrows, so no orphaned account is left. The provider receives the new `pacc` id as `data.account_id` and as the default `context.idempotency_key`. Stripe Connect stores that id in the Stripe account’s `metadata.account_id`, which is how webhooks find the account later.
