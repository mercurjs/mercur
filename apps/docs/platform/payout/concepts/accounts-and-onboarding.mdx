A payout account is a seller’s connection to the payout provider, and onboarding is the provider-side setup the seller completes before money can reach them. You need both before you can pay a seller. Mercur stores the provider’s own data on each record without reading it, so the same records work for any provider.

## The payout account

A payout account is the record a payout is sent to. It’s the `PayoutAccount` data model (table `payout_account`, id prefix `pacc`), and the `seller_payout_account` link ties it to exactly one seller.

You create one with `createPayoutAccountWorkflow`. The workflow checks the seller has no account yet, asks the module to create the account, and links it to the seller:

```ts
import { createPayoutAccountWorkflow } from "@mercurjs/core/workflows"

const { result } = await createPayoutAccountWorkflow(container).run({
  input: {
    seller_id: "sel_01JD8Q1234567",
    data: { country: "US" },
  },
})
```

Inside the module, `createPayoutAccount` runs 3 writes in order:

1. Create the `PayoutAccount` row with your `data` and `context`
2. Call the provider’s `createAccount` with `data.account_id` and `metadata.account_id` set to the new `pacc` id, and `context.idempotency_key` defaulting to the same id
3. Store the provider’s account id as `external_id`, its flags, the derived `status` and `kyc_status`, and its `data`

If the provider call throws before an account exists, the module deletes the new row and rethrows. The Stripe Connect provider creates an Express account and returns it as `pending`. The built-in `system` provider returns an `active` account at once.

With the `onboarding.prefill` option, the module also passes the seller’s name, website, email, phone, country, and business type, so the provider can prefill its forms. `onboarding.defaultCountry` applies when the seller has no address.

`ensureSellerPayoutAccountWorkflow` wraps both steps for one seller: it creates the account when it’s missing, and publishes an onboarding link until the seller has submitted their details. Run it again as often as you like.

<Note>
  A seller can have only one payout account. `validateSellerPayoutAccountStep` queries `seller_payout_account` and fails with `Seller already has a payout account` when a row exists.
</Note>

## Onboarding

Onboarding is the provider’s setup flow: identity checks, bank details, and anything else the provider needs. Its state lives in the `Onboarding` data model (table `onboarding`, id prefix `onb`), a one-to-one child of the payout account.

`createOnboardingWorkflow` takes an `account_id` and calls the provider’s `createOnboarding` with the account’s `external_id`, a `refresh_url`, and a `return_url`. By default both URLs come from the module’s `onboarding` options: `return_url` is `onboarding.returnUrl`, and `refresh_url` is `<onboarding.refreshBaseUrl>/payout/onboarding/refresh?token=<onboarding_token>`. Pass them in `data` to override:

```ts
import { createOnboardingWorkflow } from "@mercurjs/core/workflows"

const { result } = await createOnboardingWorkflow(container).run({
  input: {
    account_id: "pacc_01JD8Q1234567",
    data: {
      refresh_url: "https://vendor.example.com/payouts/refresh",
      return_url: "https://vendor.example.com/payouts",
    },
  },
})
```

The result’s `data` holds what the provider returned, plus `url`, `kind` (`onboarding` or `login`), and `expires_at`. For Stripe Connect, `data.url` is the hosted onboarding page. The workflow is safe to re-run:

- **First run**: creates the `Onboarding` record
- **Later runs**: update the same record with new provider data, which you need when a Stripe link expires

## Provider data and context

Every payout record has a `data` JSON field, and accounts and onboarding records also have `context`. They play different roles:

- **`data`**: the provider’s durable payload, such as the Stripe account, the account link, or the transfer behind a payout
- **`context`**: per-call hints for the provider, today only `idempotency_key`

The module never interprets `data`. It passes it to the provider and stores what comes back. When you switch providers, the records keep the same shape.

<Warning>
  A payout account’s `data` holds the raw provider object. For Stripe Connect, that’s the full `Stripe.Account`, so select only the fields you need before you return it from a public route.
</Warning>
