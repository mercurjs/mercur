The Payout module never references other modules directly. 3 module links in `packages/core/src/links` connect its records to sellers and orders. Read across them with `query.graph`, and query a link’s own table by its entry name.

| Link | Entry name | Cardinality | Created by |
| --- | --- | --- | --- |
| Seller ↔ payout account | `seller_payout_account` | One to one | `createPayoutAccountWorkflow` |
| Payout ↔ seller | `payout_seller` | Many payouts to one seller | `createPayoutWorkflow` |
| Order ↔ payout | `order_payout` | One order to many payouts | Nothing in core |

## Seller and payout account

Defined in `seller-payout-account-link.ts` between `SellerModule.linkable.seller` and `PayoutModule.linkable.payoutAccount`. Neither side is a list, so a seller has one payout account and an account belongs to one seller. `validateSellerPayoutAccountStep` enforces the one-account rule before a new link is created.

```ts
const { data: [seller] } = await query.graph({
  entity: "seller",
  fields: ["id", "name", "payout_account.id", "payout_account.status"],
  filters: { id: "sel_01JD8Q1234567" },
})
```

## Payout and seller

Defined in `payout-seller-link.ts` between `PayoutModule.linkable.payout`, marked `isList: true`, and `SellerModule.linkable.seller`. A seller has many payouts, and each payout has one seller. `createPayoutWorkflow` creates this link right after the payout.

```ts
const { data: payouts } = await query.graph({
  entity: "payout",
  fields: ["id", "amount", "status", "seller.id", "seller.name"],
  filters: { status: "paid" },
})
```

The Vendor API scopes payouts by querying the link table directly, with `entity: "payout_seller"` and filters on `seller_id` and `payout_id`.

## Order and payout

Defined in `order-payout-link.ts` between Medusa’s `OrderModule.linkable.order` and `PayoutModule.linkable.payout`, marked `isList: true`. An order can have many payouts.

<Warning>
  No workflow in core creates `order_payout` rows, so `order.payouts` is empty by default. To use this link, create it in the `payoutCreated` hook of `createPayoutWorkflow`, which receives `order_id` and `payout_id`.
</Warning>

```ts title="src/workflows/hooks/link-payout-to-order.ts"
import { createPayoutWorkflow } from "@mercurjs/core/workflows"
import { ContainerRegistrationKeys, Modules } from "@medusajs/framework/utils"
import { MercurModules } from "@mercurjs/types"

createPayoutWorkflow.hooks.payoutCreated(
  async ({ order_id, payout_id }, { container }) => {
    const link = container.resolve(ContainerRegistrationKeys.LINK)

    await link.create({
      [Modules.ORDER]: { order_id },
      [MercurModules.PAYOUT]: { payout_id },
    })
  }
)
```

Once the hook runs, read an order’s payouts with `fields: ["id", "payouts.id", "payouts.status"]` on the `order` entity.
