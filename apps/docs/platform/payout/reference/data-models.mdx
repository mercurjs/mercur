The Payout module owns 4 data models: `PayoutAccount`, `Onboarding`, `Payout`, and `PayoutReversal`. They’re defined in `packages/core/src/modules/payout/models`, and the module service is registered as `MercurModules.PAYOUT`. Every model also gets Medusa’s `created_at`, `updated_at`, and `deleted_at` columns.

The module has no provider table and no `provider_id` columns: a marketplace has exactly one payout provider.

## PayoutAccount

A seller’s connection to the payout provider. Table `payout_account`, id prefix `pacc`.

| Field | Type | Description |
| --- | --- | --- |
| `id` | `text` | Primary key, such as `pacc_01JD8Q1234567` |
| `provider_account_id` | `text`, nullable | The provider’s account id, such as a Stripe `acct_…` id. Unique when set |
| `status` | `enum` | `PayoutAccountStatus`, default `pending` |
| `kyc_status` | `enum`, nullable | `PayoutKycStatus`, derived from the provider’s requirements |
| `payouts_enabled` | `boolean` | Mirrors the provider, default `false` |
| `charges_enabled` | `boolean` | Mirrors the provider, default `false` |
| `details_submitted` | `boolean` | Mirrors the provider, default `false` |
| `disabled_reason` | `text`, nullable | The provider’s reason for disabling the account |
| `requirements` | `json`, nullable | `currently_due`, `past_due`, and `pending_verification` lists |
| `onboarding_token` | `text`, nullable | Secret for the public refresh URL. Unique when set, cleared once details are submitted |
| `last_synced_at` | `dateTime`, nullable | When the account was last read from the provider |
| `data` | `json` | Provider account data, default `{}` |
| `context` | `json`, nullable | Provider context passed at creation |

Relations:

- **`onboarding`**: `hasOne` `Onboarding`, nullable, mapped by `account`
- **`payouts`**: `hasMany` `Payout`, mapped by `account`

The seller is reached through the `seller_payout_account` link, not a column. See [Links](/platform/payout/reference/links).

## Onboarding

The provider’s onboarding state for one payout account. Table `onboarding`, id prefix `onb`.

| Field | Type | Description |
| --- | --- | --- |
| `id` | `text` | Primary key, such as `onb_01JD8Q1234567` |
| `data` | `json`, nullable | Provider link data plus `url`, `kind` (`onboarding` or `login`), and `expires_at` |
| `context` | `json`, nullable | Provider context from the last onboarding call |
| `account_id` | `text` | Foreign key to `PayoutAccount` |

Relations:

- **`account`**: `belongsTo` `PayoutAccount`, mapped by `onboarding`

## Payout

The seller’s share of one order, sent to their payout account. Table `payout`, id prefix `pout`.

| Field | Type | Description |
| --- | --- | --- |
| `id` | `text` | Primary key, such as `pout_01JD8Q1234567` |
| `display_id` | `autoincrement` | Human-readable sequence number |
| `order_id` | `text`, nullable | The order paid out. Unique when set, so an order is paid once |
| `currency_code` | `text` | Currency of the payout |
| `amount` | `bigNumber` | Order total minus commission, net of refunds that landed before the payout |
| `status` | `enum` | `PayoutStatus`, default `pending` |
| `status_reason` | `text`, nullable | Why the payout is on hold, failed, or aborted |
| `provider_payout_id` | `text`, nullable | The provider’s id, such as a Stripe transfer id |
| `data` | `json`, nullable | `attempts`, `source_payment`, `absorbed_refund_ids`, and the provider response under `provider` |
| `metadata` | `json`, nullable | Your own data |
| `account_id` | `text` | Foreign key to `PayoutAccount` |

Relations:

- **`account`**: `belongsTo` `PayoutAccount`, mapped by `payouts`
- **`reversals`**: `hasMany` `PayoutReversal`, mapped by `payout`, deleted with the payout

Indexes, all limited to rows where `deleted_at IS NULL`:

- **`IDX_payout_account_id_created_at`**: on `account_id`, `created_at`
- **`IDX_payout_status_created_at`**: on `status`, `created_at`
- **`IDX_payout_order_id`**: unique on `order_id` when set
- **`IDX_payout_provider_payout_id`**: on `provider_payout_id` when set

## PayoutReversal

One refund’s share taken back from a payout, the way Medusa keeps a `Refund` under a `Payment`. Table `payout_reversal`, id prefix `pourev`.

| Field | Type | Description |
| --- | --- | --- |
| `id` | `text` | Primary key |
| `refund_id` | `text`, nullable | The Medusa refund reversed. Unique when set |
| `amount` | `bigNumber` | The refund minus its share of the commission |
| `status` | `enum` | `PayoutStatus`, default `pending` |
| `status_reason` | `text`, nullable | Why the reversal is on hold, failed, or aborted |
| `provider_reversal_id` | `text`, nullable | The provider’s id, such as a Stripe transfer reversal id |
| `data` | `json`, nullable | `attempts` and the provider response under `provider` |
| `payout_id` | `text` | Foreign key to `Payout` |

Relations:

- **`payout`**: `belongsTo` `Payout`, mapped by `reversals`
