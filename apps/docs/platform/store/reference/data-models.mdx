The Seller module (`MercurModules.SELLER`) owns the store, its business details, and its team. Every model also has the standard `created_at`, `updated_at`, and `deleted_at` columns, which the tables below leave out.

## Seller

The store account and its public profile. Table `seller`, id prefix `sel`.

| Field | Type | Description |
| --- | --- | --- |
| `id` | `text` | Primary key |
| `name` | `text` | Searchable, unique |
| `handle` | `text` | Searchable, unique, generated from `name` when omitted |
| `email` | `text` | Searchable, unique |
| `phone` | `text` | Nullable |
| `description` | `text` | Nullable |
| `logo` | `text` | Nullable, image URL |
| `banner` | `text` | Nullable, image URL |
| `website_url` | `text` | Searchable, nullable |
| `external_id` | `text` | Searchable, nullable, unique when set |
| `currency_code` | `text` | The store’s settlement currency |
| `status` | `enum` | `SellerStatus`, default `pending_approval` |
| `status_reason` | `text` | Nullable, set by suspend and terminate |
| `approved_at` | `dateTime` | Nullable, set on first approval |
| `rejected_at` | `dateTime` | Nullable, set on first suspension |
| `is_premium` | `boolean` | Default `false` |
| `default_leadtime_to_ship` | `number` | Default `2`, in days |
| `closed_from` | `dateTime` | Nullable, start of a scheduled closure |
| `closed_to` | `dateTime` | Nullable, end of a scheduled closure |
| `closure_note` | `text` | Nullable |
| `metadata` | `json` | Nullable |

Unique indexes on `name`, `handle`, `email`, and `external_id` apply only to rows that aren’t deleted. An extra index on `(status, closed_from, closed_to)` serves the Store API visibility filter.

Relations:

- **`professional_details`**: has one `ProfessionalDetails`, deleted with the seller
- **`address`**: has one `SellerAddress`, deleted with the seller
- **`payment_details`**: has one `PaymentDetails`, deleted with the seller
- **`members`**: many-to-many with `Member` through `SellerMember`, detached when the seller is deleted
- **`member_invites`**: has many `MemberInvite`, deleted with the seller

## Member

A person who can work for one or more stores. Table `member`, id prefix `mem`.

| Field | Type | Description |
| --- | --- | --- |
| `id` | `text` | Primary key |
| `email` | `text` | Searchable, unique across the marketplace |
| `first_name` | `text` | Searchable, nullable |
| `last_name` | `text` | Searchable, nullable |
| `locale` | `text` | Nullable |
| `is_active` | `boolean` | Default `true` |
| `metadata` | `json` | Nullable |

Relations: `sellers`, many-to-many with `Seller` through `SellerMember`.

## SellerMember

One member’s membership in one store. Table `seller_member`, id prefix `selmem`, unique on `(seller_id, member_id)`.

| Field | Type | Description |
| --- | --- | --- |
| `id` | `text` | Primary key |
| `seller_id` | `text` | Belongs to `Seller` |
| `member_id` | `text` | Belongs to `Member` |
| `role_id` | `text` | Nullable, a `SellerRole` value |
| `is_owner` | `boolean` | Default `false` |
| `metadata` | `json` | Nullable |

## MemberInvite

A pending invitation to join a store. Table `member_invite`, id prefix `meminv`.

| Field | Type | Description |
| --- | --- | --- |
| `id` | `text` | Primary key |
| `email` | `text` | Searchable, the invited address |
| `token` | `text` | Signed JWT, indexed |
| `accepted` | `boolean` | Default `false` |
| `expires_at` | `dateTime` | Set by the service, 7 days out by default |
| `role_id` | `text` | The `SellerRole` the member gets on accept |
| `seller_id` | `text` | Belongs to `Seller` |
| `metadata` | `json` | Nullable |

A unique index on `(email, seller_id)` covers invites that aren’t accepted or deleted, so a store has one open invite per email.

## OrderGroup

The Seller module also holds the `OrderGroup` model, which groups the per-store orders split from one cart. See the [order group data models](/platform/order-group/reference/data-models) for its fields.
