Run `linkSellersToProductWorkflow` to change which stores can see and sell a master product. Use it for exclusive ranges, authorized resellers, or to restrict a store's own submission after review.

## Before you begin

Know how the list behaves before you change it:

- **Empty list**: every store can sell the product
- **One or more stores**: only those stores can sell it

Read [the store allowlist](/platform/catalog/concepts/product-seller-allowlist) for where Mercur enforces it.

## Change a product's allowlist

<Steps>
  <Step title="Add a route that runs the workflow">
    The workflow takes the product `id` and optional `add` and `remove` arrays of seller ids. It writes and deletes `product_seller` rows in one run.

    ```ts title="src/api/admin/exclusive-products/[id]/route.ts"
    import type {
      MedusaRequest,
      MedusaResponse,
    } from "@medusajs/framework/http"
    import { linkSellersToProductWorkflow } from "@mercurjs/core/workflows"

    type Body = { add?: string[]; remove?: string[] }

    export async function POST(
      req: MedusaRequest<Body>,
      res: MedusaResponse
    ) {
      await linkSellersToProductWorkflow(req.scope).run({
        input: { id: req.params.id, ...req.body },
      })

      res.json({ id: req.params.id })
    }
    ```

    If a step fails, the workflow undoes the rows it already changed.
  </Step>
  <Step title="Check the result">
    Read the product's `sellers` to confirm the new list.

    ```ts
    const { data: [product] } = await query.graph({
      entity: "product",
      fields: ["id", "sellers.id"],
      filters: { id: "prod_01JD8Q1234567" },
    })
    ```

    `product.sellers` holds every store on the list. An empty array means the product is open to all stores.
  </Step>
</Steps>

## Open a product to every store again

Remove every store on the list. Read the current stores first, then pass all of them in `remove`.

```ts
const { data: [product] } = await query.graph({
  entity: "product",
  fields: ["sellers.id"],
  filters: { id: "prod_01JD8Q1234567" },
})

await linkSellersToProductWorkflow(container).run({
  input: {
    id: "prod_01JD8Q1234567",
    remove: (product.sellers ?? []).map((seller) => seller.id),
  },
})
```

The product now has no `product_seller` rows, so every store can see and sell it once it's published.

## Check the allowlist before creating offers

`createOffersWorkflow` doesn't read the allowlist. If your code creates offers for stores, read the product's `sellers` as shown above and check that the store may sell it first.

```ts
import { MedusaError } from "@medusajs/framework/utils"

const sellerIds = (product.sellers ?? []).map((seller) => seller.id)
const allowed =
  sellerIds.length === 0 || sellerIds.includes("sel_01JD8Q1234567")

if (!allowed) {
  throw new MedusaError(
    MedusaError.Types.NOT_ALLOWED,
    "This store can't sell the product"
  )
}
```

`allowed` is true when the list is empty or names the store. Removing a store from the list later doesn't delete the offers it already has.

## Link stores to a category

`linkSellersToProductCategoryWorkflow` writes the `category_seller` link with the same input shape.

```ts
import { linkSellersToProductCategoryWorkflow } from "@mercurjs/core/workflows"

await linkSellersToProductCategoryWorkflow(container).run({
  input: { id: "pcat_01JD8Q1234567", add: ["sel_01JD8Q1234567"] },
})
```

Mercur doesn't filter products by this link. Run `validateSellerProductPermissionsStep` in your own workflow if you want linked stores blocked from a category.
