Panel extensions let you customize the Admin and Vendor panels without forking them.

You drop a file into a panel's `src/` and one of four helpers registers it at
build time: `defineWidgetConfig` attaches a component to a zone,
`defineCustomFieldsConfig` extends a model's forms and tables,
`defineNavigationConfig` reshapes the sidebar, and `createFormHelper` types a
form's fields and values. The [Extend forms and tables](/rc/resources/tutorials/extend-forms-and-tables),
[Add a widget](/rc/resources/tutorials/add-a-widget), and
[Customize navigation](/rc/resources/tutorials/customize-navigation) tutorials
walk through building an extension. These pages document the exact config shape of
each helper and the props each component you pass in receives at render time.

## Separate apps, no surface field

Admin (`@mercurjs/admin`, port 7000) and vendor (`@mercurjs/vendor`, port 7001)
are separate Vite apps. A file dropped under a panel's `src/` targets that panel,
so the folder you author in is the surface and there is no `surface` field to set.
The helpers are the same in both. Import the config helpers from
`@mercurjs/dashboard-sdk` and `createFormHelper` from `@mercurjs/dashboard-shared`.

## Typed targets

Zone ids, nav item ids, models, and built-in field ids are typed per panel from a
generated `extension-targets.d.ts`. Reference it once per host app so every
extension file type-checks with no per-file import:

```typescript apps/vendor/src/extension-targets.d.ts
/// <reference types="@mercurjs/vendor/extension-targets" />
```

```typescript apps/admin-test/src/extension-targets.d.ts
/// <reference types="@mercurjs/admin/extension-targets" />
```

A wrong `zone`, `model`, or nav `id` fails `tsc` (`bun run lint`) rather than
silently no-op'ing at runtime.

## Persistence

<Warning>
  **The MVP is a UI surface only.** Custom fields render, validate, and display
  through the built-in forms, sections, and tables. There is no generic core-side
  write path. For `product`, values are submitted under `additional_data` and
  persisted onto `metadata`. To store data for other models, wire your own
  route or workflow, or use the backend
  [Custom Fields module](/rc/resources/customization/custom-fields).
</Warning>
