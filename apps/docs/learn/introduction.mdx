## What is Mercur

Mercur is the open-source enterprise marketplace platform built on Medusa. Medusa
provides the commerce engine (products, pricing, carts, orders, fulfillment, and
payments), and Mercur adds the marketplace layer on top: sellers and their teams,
onboarding, the catalog change pipeline, commissions, order splitting, and vendor
payouts.

It gives a marketplace operator real governance: role-based access control, an
auditable change pipeline, and per-seller settlement, while staying composable,
API-first, and fully code-owned. You run it on your own infrastructure.

## Install

Create a new project with the CLI. It downloads a template, installs
dependencies, creates and migrates the database, seeds data, and starts the dev
server.

<Steps>
  <Step title="Check the requirements">
    Node.js v20+, Bun v1.3+, Git, and PostgreSQL v14+. See [Installation](/learn/installation) for a Docker one-liner to run Postgres locally.
  </Step>
  <Step title="Create a project">
    ```bash
    bun create mercur-app@latest
    ```

    The CLI prompts for a project name and a template (`basic` or `plugin`), then sets everything up for you.
  </Step>
  <Step title="Open your marketplace">
    Once the server is running, the surfaces are available at:

    | Surface | URL |
    | --- | --- |
    | API | `http://localhost:9000` |
    | Admin Panel | `http://localhost:9000/dashboard` |
    | Vendor Panel | `http://localhost:9000/seller` |

    The CLI opens the admin setup page so you can create your first operator account.
  </Step>
</Steps>

For the full setup, database options, and how to initialize Mercur in an existing
Medusa project, see [Installation](/learn/installation).

## What you get

A Mercur project ships three role-based surfaces backed by the marketplace
modules.

- **Admin Panel** (`/dashboard`): the operator dashboard for sellers, catalog, orders, commissions, and payouts.
- **Vendor Panel** (`/seller`): the seller portal for a store's own offers, orders, and payouts.
- **Store API** (`/store/*`): the storefront API for discovery, multi-vendor carts, and checkout.

Underneath, the platform modules own each domain: **Store** (sellers, teams,
RBAC), **Catalog** and **Offer** (the shared master catalog and per-seller
listings), **Commission** and **Payout** (settlement), **Order Group** (the
multi-vendor order split), **Product Edit** (the auditable change pipeline), and
**Review**.
