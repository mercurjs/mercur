Mercur is the open-source **enterprise marketplace platform** built on Medusa. It
gives a marketplace operator the governance to run a multi-vendor business at
scale: role-based access control, an auditable change pipeline, approval
workflows, and multi-vendor settlement. It stays composable, API-first, and
AI-native, and you run it on your own infrastructure with full code ownership.

## What is Mercur

Medusa provides the commerce engine: products, pricing, carts, orders,
fulfillment, and events. Mercur builds the marketplace domain layer on top:
sellers and their teams, onboarding, the catalog change pipeline, commissions,
reviews, returns, order splitting, and vendor payouts, plus dedicated Admin,
Vendor, and Store APIs.

It ships three optional interfaces:

- an **Admin Panel** for marketplace operators
- a **Vendor Portal** for seller teams
- a **Storefront** ready for marketplace scenarios

## Enterprise-grade governance

Running a marketplace means governing who sells, what they change, and how they
get paid. Mercur builds that in.

- **Role-based access control:** members belong to sellers with roles resolved per store, backed by the roles module Mercur registers out of the box. Access to one store never leaks into another.
- **An auditable change pipeline:** every catalog edit flows through immutable, attributed change records with an approval queue, so you always know who changed what and who approved it.
- **Approval governance:** seller onboarding and product changes move through explicit lifecycles that an operator controls.
- **Settlement you control:** per-seller commissions, order splitting, and provider-driven payouts (with KYC handled by the payout provider) settle each seller independently.
- **Full code ownership:** blocks are copied into your project as source, so you own every line and can host it anywhere, with no black-box dependencies.

See [Security and governance](/learn/security-and-governance) for the full picture.

## Why Mercur

Composable, open, and code-owned is not a step down from enterprise. It is how
Mercur is a better enterprise choice than a closed platform.

- **Composable and code-native:** install only the modules, workflows, API routes, and UI extensions you need, and modify any of them without forking.
- **Open-core, MIT-licensed:** no transaction fees, no commercial lock-in, and no constraints on how your marketplace behaves.
- **Own the whole stack:** you hold the entire codebase and deploy it on your own infrastructure.

## AI-native, enterprise-governed

Mercur is built so AI agents can extend your marketplace within guardrails, not by
generating loose code from scratch. Every surface an agent touches has a
machine-checkable contract, so a change is correct by construction or it fails to
compile.

- **Typed contracts:** the generated API client means an agent reads real types, not documentation that may be stale. Wrong calls do not compile.
- **Composable blocks:** features are discrete units an agent can inspect before installing and verify after.
- **Workflow hooks:** an agent extends core flows such as `complete-cart-with-split-orders` through hooks, not by patching source.
- **File-based routing:** an agent adds an admin or vendor page by creating a file, and the dashboard SDK registers it.
- **Bundled, version-matched docs:** agents read docs shipped inside your project, so they build from your installed version, not training data.
